# Databel Churn — Power BI project

A 4-page executive report on Databel customer churn, saved as a Power BI Project
(PBIP) with a TMDL semantic model and a PBIR report.

**Live interactive version:** https://junayedparves.github.io/Databel-Churn-PowerBI/
is a browser replica of all four pages with filters (state, age group, contract type,
gender), computed from the same CSV. You don't need Power BI to view it.

| Page | What it shows |
|---|---|
| 1 Executive Summary | KPI row, churn categories, top 5 reasons, recommendations |
| 2 Contract & Tenure | Churn by contract, tenure and payment method (headline is a live measure) |
| 3 Service & Plan Fit | Churn by support calls, international-plan fit matrix, plans and add-ons |
| 4 Who Churns | Age, senior × contract, group vs individual, gender, top 10 states |

## Open the project

0. Clone or download this repository. The dataset is included at `data/Databel - Data.csv`.
1. Power BI Desktop → **File › Options and settings › Options › Preview features**, make sure these are ticked
   (restart Desktop after changing them):
   - **Power BI Project (.pbip) save option**
   - **Store semantic model using TMDL format**
   - **Store reports using enhanced metadata format (PBIR)**
2. Open `Databel Churn.pbip`.
3. The project ships without a data cache, so the first time you'll see a yellow banner:
   click **Refresh now** (or **Home › Refresh**), then **File › Save**. Saving writes
   `.pbi/cache.abf` so later opens show data immediately.

No other preview features are needed. The report uses no map visual (see below).

## Point it at your data (`DataFolder` parameter)

The CSV path is held in a text parameter, `DataFolder`. The query reads
`DataFolder\Databel - Data.csv` (a trailing `\` is optional). Power Query only accepts
absolute paths, and the default is the author's checkout of the `data/` folder
(`C:\Users\Junayed\Desktop\Power BI Dashboard\Databel Churn\data`).
**After cloning, set DataFolder to your own `…\data` folder before refreshing.**

To change it, go to **Home › Transform data › Edit parameters**, set **DataFolder** to the folder
that contains `Databel - Data.csv`, then click **Apply changes** and **Refresh**.

To change it without opening Desktop, edit the path in
`Databel Churn.SemanticModel/definition/expressions.tmdl`.

## Check the numbers

```
pip install pandas
python validate.py                      # or: python validate.py "D:\path\to\folder"
```

`validate.py` rebuilds the model logic in pandas and checks every validation figure from
the brief (totals, contract, tenure, payment, service calls, plan fit, age, senior × contract).

## Rebuild the project files

The PBIP is generated by `_build/generate_pbip.py`, and every page, visual and measure is
defined there. Regenerating also resets DataFolder to your checkout's `data/` folder.
After editing it:

```
python _build/generate_pbip.py
python _build/validate_report.py        # JSON parse + field-reference check + Microsoft PBIR validator
```

`validate_report.py` needs `npm install -g @microsoft/powerbi-report-authoring-cli`.
Regenerating overwrites the `definition` folders, so re-apply any edits you made in Desktop
to the generator instead.

## Where the report differs from the brief

| Brief | What was built | Why |
|---|---|---|
| Filled map / Shape map of churn by state (page 4) | **Top 10 states table** with in-cell data bars (State, Customers, Churn). The CA churn value is orange. | Current Power BI Desktop blocks Shape Map and Filled Map (`FilledMapVisualNotEnabled`); Azure Maps would send state names to an online service. You asked for a non-map visual. |
| Top 5 states table | Top 10, in the space the map would have used | The table now carries the whole state view |
| Top N on reasons "by Churned Customers" | Top N by **count of Churn Reason** | Gives the same result, because only churners have a reason. A Top N ranked by a measure is a known Desktop crash risk. The states table does rank by the Churn Rate measure and renders correctly. |
| Blank Churn Category / Reason "left blank" | Empty text is turned into true nulls in Power Query | Needed so "blanks filtered out" and the reason count work; the displayed values are unchanged |
| Page navigator x 800, w 440 | x 680, w 560 | At 440px the tab names were cut off ("Contract &…") |
| Headline text box h 90 | h 96, with 0 padding | Two-line 20pt headlines plus the subtitle overflowed at 90px |
| Slicers y 150, h 44 | y 154, h 52 | Dropdowns clipped below 48px; the header needs a little more |
| KPI subtitle "reference label or stacked text" | The card's category label, placed below the value. On the Revenue Lost and Group cards it is bound to the subtitle measures (Revenue Lost Subtitle, Group Subtitle). | This is the new card's native subtitle slot and it updates with slicers |
| KPI 3px top accent on the card | A 3px shape laid over the card's top edge | The card's own accent bar draws below the title, not at the top |
| "So what" 3px orange bar above the box | A separate 3px shape | Textboxes can't draw a single-side border |
| Contract headline bound to the measure | A dynamic text box value | The text wraps and updates with slicers. In edit view Desktop draws a thin accent-coloured line under a bound value; check reading view. |
| Headline sentence on page 2 | Reads "**17×**" | The Contract Headline measure rounds 46.3% ÷ 2.8% = 16.6 up; the mockup said 16× |
| Plans and add-ons colours | All grey | The Churn Colour rule is applied as specified; no plan segment is at or above 35% (Unlimited data "Yes" is 32.1%) |
| Headline font | Segoe UI Semibold, 20pt | The mockup used Source Serif; the brief specified Segoe |
| Theme file name | `Databel_Executive-<hash>.json` | Desktop caches themes by name, so a content hash makes theme edits reload. The theme's content is otherwise unchanged. |
